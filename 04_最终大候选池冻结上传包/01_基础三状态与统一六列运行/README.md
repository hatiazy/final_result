# 基础三状态与统一六列冻结运行

这是统一的日常运行入口。`packages/nonzero/1545/src/common/spot_eight_state.py` 和同目录的冻结配置从远端纯现货生成基础三状态；随后 V55、V80、V156、V189 生成最终六列表。这里运行的是已经冻结的参数，不重新遍历大候选池。

这个包只保留两个 Notebook，分别完成“生成”和“检查”两个独立任务。

## 运行顺序

### 1. 只用远端现货生成六列表

打开并运行：

```text
01_只用远端现货生成六列.ipynb
```

它只读取远端现货路径：

```text
/home/hzy/cta/IC数据更新*最终固化版/现货最终版/CSI500_SPOT_md_eod_raw*最终版.parquet
```

也支持已经配置好的 `COMPANY_SPOT_PATH`。如果远端路径不存在，它会直接报错，不会回退到本地数据。

这个 Notebook 使用包内冻结的四组参数：

| 信号 | 冻结版本 | 参数 |
|---|---|---|
| -1→0 | V55 | `score_02`，阈值 `0.815842643776842`，最小状态年龄 1 天，确认 2 天 |
| +1→0 | V80 | `score_02`，阈值 `0.4920211306764882`，最小状态年龄 5 天，确认 1 天 |
| 大跌 | V156 | `base_0621`，阈值 `0.6832148298881413` |
| 大涨 | V189 | `base_1839`，阈值 `0.8135114753699175` |

输出为：

```text
runtime_outputs/最终执行日简表.csv
```

列固定为：

```text
实际执行日、三状态、+1反转、-1反转、大涨、大跌
```

同时会在 `runtime_outputs/_engine_outputs/` 保存生成过程的内部日志和中间逐日结果，但第一个 Notebook 不读取本地参考结果，也不生成任何比较结论。

## 2. 读取本地冻结数据并详细检查

确认第一个 Notebook 已经生成六列表后，打开并运行：

```text
02_六列表详细一致性检查.ipynb
```

它读取：

```text
远端生成：runtime_outputs/最终执行日简表.csv
本地参考：expected/local_freeze/最终执行日简表_本地冻结参考.csv
```

它会生成：

```text
runtime_outputs/六列表逐日对比.csv
runtime_outputs/六列表一致性结论.json
runtime_outputs/六列表不一致示例.csv
```

重点看：

- `success` 是否为 `True`；
- 远端和本地日期范围是否一致；
- `remote_only_rows` 和 `local_only_rows` 是否为 0；
- 三状态、+1 反转、-1 反转、大涨、大跌五个字段的不一致行数是否全部为 0。

## 是否遍历候选

不会。

第一个 Notebook 使用的是已经冻结的最终版本和阈值：

- V55/V80 只计算冻结的 `score_02` 和冻结规则；
- V156/V189 只计算冻结的基础分数列和冻结阈值；
- 不重建候选池；
- 不重新排序候选；
- 不根据远端 Test 重新选择版本；
- 不读取本地预测结果参与生成。

因此它会比全量候选搜索快很多。仍然需要读取完整历史现货并计算滚动特征，所以不是瞬间完成，但运行量已经从候选遍历降为四个冻结信号的直接复现。

## 训练、验证和测试集口径

四个版本的冻结结论遵循以下流程：

1. 在 Development 上拟合或确定阈值；
2. 用 Development 和 Validation 的冻结结果进行版本/规则的研究筛选；
3. 在冻结之后才解锁 Test；
4. Test 只作为冻结版本的观察结果，不参与候选选择、阈值重新拟合或版本回写；
5. 远端更新现货后，只把冻结参数应用到新增和历史现货上，输出最新执行日六列表。

因此，06 包生成的最新六列表是“冻结后在 Test/最新区间上的复现和观察”，不是重新训练后的结果。第二个 Notebook 的检查也只检查远端生成结果和本地冻结参考是否逐日逐列一致，不会改变任何参数。
