# 最终大候选池冻结上传包

这里是四类最终材料的唯一正式入口：基础三状态、长0两侧转移、1545涨跌反转、大涨大跌预测。

## 四类内容

| 目录 | 内容 | 研究阶段候选池 |
|---|---|---:|
| `01_基础三状态与统一六列运行` | 基础三状态现货生成、四个冻结信号的六列表运行与逐日检查 | 统一运行入口，不重新选参 |
| `02_长0两侧转移` | `0→-1`、`0→1` 的完整公司端候选池冻结上传包；同时导出事件式三状态 | 6,144 + 6,144 = 12,288 |
| `03_1545涨跌反转` | `-1→0`、`1→0` 的完整公司端候选池冻结上传包；同时生成最终五列三状态信号 | 15,552 + 7,776 |
| `04_大涨大跌预测` | 大涨/大跌候选池研究引擎、冻结产物和冻结后运行包 | 每侧 49,152 |
| `05_冻结登记与候选池证据` | 四个最终信号的版本、候选池规模、冻结流程和审计证据 | 统一登记 |

## 怎么用

- 日常更新六列表：进入 `01_基础三状态与统一六列运行`，运行 `01_只用远端现货生成六列.ipynb`。
- 需要重跑长0完整大池：进入 `02_长0两侧转移/完整候选池冻结上传包`。
- 需要重跑1545完整大池：进入 `03_1545涨跌反转/完整候选池冻结上传包`。
- 需要复核大涨/大跌候选池：进入 `04_大涨大跌预测/01_候选池研究与冻结`；需要日常复现冻结版本时使用 `02_最终冻结运行`。
- 需要核对候选池规模、最终 Top1 和 Test 隔离：进入 `05_冻结登记与候选池证据`。

## 口径边界

长0和1545目录中的包是完整候选池上传包：公司端会重建各侧完整候选网格，在 Development+Validation 中冻结 Top1，冻结后才观察 Test。大涨/大跌目录同时保留完整研究候选引擎与最终冻结运行包；日常冻结运行只计算已经冻结的 V156/V189，不重新遍历 49,152 个候选。基础三状态是四类信号共同使用的现货状态生成链路，不单独再复制一套候选池。

根目录的 `05_上传包_日期解析修正版` 仍保留为历史验证工程包，不作为最终入口；`99_中间归档` 只保留其他中间过程，不再放最终上传包。
