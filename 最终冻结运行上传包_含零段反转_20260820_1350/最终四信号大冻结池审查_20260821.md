## 一、最终结论

1. **最终四个信号的正式候选筛选没有使用 Test 指标反向筛选。**
   - Development：2018-01-01 至 2022-12-31；
   - Validation：2023-01-01 至 2024-12-31；
   - Test：2025-01-01 至最新数据。
   - 正式的最终候选排序和质量门都只在 Development+Validation 上完成；零段 runner 在写入冻结前摘要后才计算 Test。非零 runner 另有“各版本 DV Top1 的 Test 观察诊断”，它不参与最终跨版本排序，详见第五节的流程说明。

2. **“Development+Validation 得分第一后观察 Test”这句话需要分两类说。**
   - `-1→0` 的 V55、`+1→0` 的 V80：最终确实是 Development+Validation 联合评分排序后的 Top1。
   - `0→-1` 的 V38、`0→+1` 的 V57：不是简单取原始主评分第一，而是在 Development+Validation 上先做事件质量、状态质量和持有段质量门，再从质量候选中冻结。因此它们是“Development+Validation 质量优先 Top1”，不是“原始排序第一”。

3. **训练和验证表现总体为正，但强弱不均。**
   - V55、V38 的 Development/Validation 方向化 O2O H1 都为正，V80 的 Development/Validation 也较好；
   - V57 的 Development H3 只有约 2.52 bp，Test H1 只有约 8.95 bp，Test Rank IC 为负，是四个信号中最弱、最需要保守表述的一个；
   - 所以可以说“冻结流程严谨、开发/验证有正向描述性证据”，不能说“四个信号都已经被 Test 证明稳定有效”。

4. **生产运行没有针对 Test 设置特殊参数或特殊规则。** 生产包只应用已经冻结的版本、阈值、状态年龄、确认、持有、释放和冷却参数；最新形成日没有未来 O2O 标签时仍可生成下一执行日信号，这是统一的实时运行规则，不是 Test 专门规则。

5. **日期和收益口径确认如下：**

   ```text
   第一天：t 日收盘形成信号
   第二天：下一实际交易日 t+1 开盘执行；非零退出在这里减仓/退出
   第三天：t+2 开盘
   O2O H1 = Open(t+2) / Open(t+1) - 1
   ```

   因此，“前一天收盘出信号、第二天开盘执行、第三天开盘与第二天开盘计算 O2O”这个理解是正确的。信号显示在第二天的实际执行日，而不是形成日。

## 三、非零退出：如何筛选、训练/验证表现和 Test 表现

### 3.1 筛选逻辑

非零候选的冻结函数只接收截至 2024-12-31 的物理截断面板。每个候选的阈值只在 Development 样本上计算；候选信号在 Development 和 Validation 上评价。

主评价指标为方向化 O2O H1：

```text
负向退出：directional_H1 = - O2O_H1
正向退出：directional_H1 = + O2O_H1
```

候选必须满足：

```text
Development 触发数 ≥ 12
Validation 触发数 ≥ 8
Development 方向化 H1 > 0
Validation 方向化 H1 > 0
```

联合评分使用 Development、Validation 和合并样本的收缩均值，并对 Development/Validation 覆盖率差异扣分：

```text
Dev 收缩均值 = Dev 均值 × Dev 触发数 / (Dev 触发数 + 8)
Val 收缩均值 = Val 均值 × Val 触发数 / (Val 触发数 + 6)
合并收缩均值 = 合并均值 × 合并触发数 / (合并触发数 + 12)

Joint Score
= 0.35 × Dev 收缩均值
 + 0.45 × Val 收缩均值
 + 0.10 × 合并收缩均值
 + 0.10 × min(Dev 收缩均值, Val 收缩均值)
 - 2 × |Dev 覆盖率 - Val 覆盖率|
```

排序后再剔除状态年龄基准信号的伪重复版本，并按 `Joint Score`、合并触发数、候选编号排序。H3、C2C、自然状态切换和 Test 指标没有进入非零正式候选筛选分数。

## 四、零段转移：质量优先冻结和训练/验证表现

### 4.1 为什么不能说是原始评分第一

零段主评分使用 Development/Validation 的百分位排名加权。权重包括：

```text
Dev H1 15%，Val H1 18%，合并 H1 10%，最差阶段 H1 7%，
合并 H1 胜率 8%，最差阶段 Rank IC 6%，合并 H3 3%，
H1/H3 路径一致性 3%，目标状态转移率 15%，
转移纯度 10%，1 - 快速恢复率 5%。
```

在此基础上，代码还对 Development/Validation 的以下内容做质量门：

- 事件 H1、H3 都为正；
- H1 胜率至少 50%；
- 目标状态转移提升为正；
- Rank IC 不低于 0；
- 转移纯度至少 60%；
- 状态路径的目标日均收益和目标段胜率为正；
- 中性段平均长度在 3–25 天，单日中性段占比不超过 15%；
- 实际持有段至少 5 段，持有段胜率至少 55%；
- 持有段方向收益和持有日方向收益为正；
- 平均持有长度在 2–12 天，单日持有段占比不超过 10%。

因此：

```text
V38：主排序基准是 V38_down_s03_a3_q0.85_c1_H04，
     但最终因 Dev/Val 状态和持有质量门，冻结为 V38_down_s01_a1_q0.85_c1_H03。

V57：主排序基准是 V57_up_s00_a1_q0.80_c2_H02，
     但最终因 Dev/Val 状态和持有质量门，冻结为 V57_up_s01_a1_q0.85_c1_H04。
```

最终策略为 `QUALITY_AWARE_FULL_GRID_DEV_VAL_ONLY`，不是 Test 质量优先。

## 五、Test 是否被用于筛选：代码级核对

### 已确认没有进入筛选的路径

1. 非零候选 `freeze_candidates` 明确拒绝包含 Test 行的冻结输入；阈值人口只取 Development，正式排名只取 Development+Validation。
2. 非零最终 Top1 写入：

   ```text
   selection_data_end = 2024-12-31
   model_fit_period = Development only
   threshold_fit_period = company Development only
   ranking_period = company Development+Validation
   test_used_for_selection = false
   ```

3. 零段 `company_pre_freeze.json` 在 Test 计算前写入，并标记：

   ```text
   test_locked_until_after_freeze = true
   test_used_for_selection = false
   ```

4. 零段最终冻结的选择策略名称本身就是 `QUALITY_AWARE_FULL_GRID_DEV_VAL_ONLY`。
5. 生产运行入口不扫描候选池、不重新选参数，也不读取未来 O2O 评价标签。

### 一个需要如实说明的流程细节

非零 `pool_runner.py` 为了生成“每个已在 Development+Validation 冻结的版本自己的 Test 观察诊断”，会在完成版本内 DV Top1 后，先计算 `version_top1_test`；这个 Test 诊断随后只作为描述性输出，不参与跨版本 `all_metrics`、`ranked` 或最终 `top1`。因此：

- **没有 Test 到最终候选的筛选依赖；**
- 但若要求“在全局最终 Top1 冻结前连 Test 都不能被读取”，非零研究 runner 的读取顺序还可以进一步收紧，把 `version_top1_test` 延后到全局 Top1 冻结之后。

这属于审计流程顺序问题，不是 Test 反向筛选问题。生产运行包本身不会执行这个研究诊断。

## 六、最终八列和信号含义

最终八列为：

```text
实际执行日、三状态、+1反转、-1反转、0转-1、0转+1、大涨、大跌
```

四个反转信号的 `1` 的含义是：对应的事件在该实际执行日触发。

| 列 | 触发条件 | 实际动作 |
|---|---|---|
| `+1反转=1` | 基础状态为 `+1`，V80 退出信号触发 | `+1→0`，减仓/退出到中性，不是直接变成 `-1` |
| `-1反转=1` | 基础状态为 `-1`，V55 退出信号触发 | `-1→0`，减仓/退出到中性，不是直接变成 `+1` |
| `0转-1=1` | 基础状态为 `0`，V38 零段向下信号触发 | 从中性进入负向方向 |
| `0转+1=1` | 基础状态为 `0`，V57 零段向上信号触发 | 从中性进入正向方向 |

当前正式八列表是 **event-only**：某个事件只在事件执行日改变标签，后续日期没有新事件时恢复基础三状态。把 `0转-1`、`0转+1` 扩展为持有期连续 1，是另一个派生输出，不应和正式事件八列表混称。

## 七、策略是否合理，以及整体结果如何表述

### 合理之处

- 特征和状态由 t 日收盘及历史数据因果生成；
- 阈值由 Development 固定，模型拟合只在 Development；
- Validation 只用于候选排序和质量检查；
- Test 没有参与最终参数选择；
- 非零退出和零段转移按不同问题分别冻结，没有把退出和入口混成一个信号；
- 有最小状态年龄、确认、最小持有、最大持有、释放和冷却，避免单日噪声直接变成连续策略；
- 生产输出按实际交易日对齐，没有用工作日偏移或默认 0 填补最新信号。

### 必须保留的边界

1. 四个信号是事件/状态调整研究，不等同于已经包含交易成本、滑点、容量和真实订单执行的完整回测。
2. 本地策略净值脚本使用 C2C 日收益做展示，而候选冻结评价使用 O2O H1；两者不能直接拿净值结果去证明候选筛选口径。
3. V57 的 Test Rank IC 为负且事件只有 15 天，汇报时应称为“有正向 H1 描述性证据，但稳健性较弱”，不能包装成稳定的正向分类器。
4. 事件日之间可能连续聚集，同一行情段内的多天信号不是完全独立样本。
5. 零段年末形成日跨到下一阶段的 O2O 标签在当前代码中是按形成日所属阶段保留的；本次按既定口径接受，不改变“Test 没有参与筛选”的结论。

## 八、最终可以对外使用的一句话

> 四个反转信号先在预注册候选池内用 2018–2022 Development 和 2023–2024 Validation 完成模型拟合、阈值冻结、候选排序和质量筛选，最终冻结 V55、V80、V38、V57；2025 年以后 Test 只作为冻结后的外样本观察，没有参与版本、阈值、状态年龄、确认、持有或冷却参数的选择。信号由前一交易日收盘形成，在下一实际交易日开盘执行，O2O H1 按下一开盘到再下一开盘计算。
